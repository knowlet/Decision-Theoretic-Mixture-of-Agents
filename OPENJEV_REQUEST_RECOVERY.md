# Exact-request forensic recovery after successful inference

All ten inference jobs in run 35310006824 succeeded. The aggregate job correctly failed on literal request SHA-256 equality during reconstruction. A local audit identified last-bit floating-point differences between CPU implementations when recomputing the training-derived candidate errors. Example: `[0.1210212854882527, 0.12100337343642713, 0.9071275039555781]` versus `[0.12102128548825267, 0.12100337343642716, 0.9071275039555782]`.

The recovery does not rerun, change, resample or select neural outputs. It searches only a fixed +/-8-ULP neighborhood of the three training-derived error values. All other fields are fixed. A recovered full request must match the original recorded SHA-256 **exactly**. An unmatchable request still fails the pipeline. This is not permission to accept approximate hashes or change gold/answers. Regression tests reject changed task text, candidate content and substantive risk drift.

Cross-model comparisons continue to use identical task identities, panels, group splits and action contracts. However, decimal request text can differ at floating-point precision across CPU hosts. The report counts those cases and explicitly does not claim byte-identical neural inputs or prove that tokenization is insensitive to the last digit. All source risk triples, ULP offsets and original hashes are published as derived diagnostic records. Future inference should generate canonical request fixtures once and share them across workers; the already-executed pilot is not silently relabeled as having done that.

The inference commit remains ee971cc25e1475ac16375886c135fe155a0dc803. Analysis/reporting changes use a separate commit and run. The failed aggregate run remains visible; a later successful analysis run validates its individually successful, hash-pinned inference artifacts. Neither is disguised as a fresh full model rerun. Primary case selection, algorithm definitions, calibration split, labels, costs and contrasts are unchanged.
